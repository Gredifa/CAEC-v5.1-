1. Introduction: The Epistemic Contract Problem

Large Language Models optimize an implicit mixture of fluency, helpfulness, safety, and perceived accuracy. This mixture shifts per task but is rarely declared explicitly.

Core Thesis:
A significant fraction of perceived LLM errors arise from misalignment between the epistemic regime expected by the user and the regime actually used by the system.
CAEC proposes: Make the epistemic contract explicit, negotiated, and auditable at inference time.

Scope: This is not a claim that all hallucinations are contract failures. This is a falsifiable hypothesis: that expectation management at inference time is an under-investigated factor in perceived model reliability.

3. Architecture v5.1

3.1 Intent + Affordance Scorer
Classifies latent intent and real-world affordance.  
If user_action(response) -> harm, then stakes=CRITICAL regardless of surface semantics like "for a novel".

3.2 Epistemic Grounding Check
Separate verifier model checks claims against verified knowledge index. Prevents "Confidence Mirage" - high confidence on false familiarity. If LLM says "Known" and Verifier says "Unknown", generation blocked.

3.3 Adaptive Decoding Policy
Confidence threshold adapts by regime: FM=0.98, AM=0.85, OC=0.60
Stakes threshold: High stakes forces clarification or abstention
Progressive Disclosure: Tags visible in FM always. AM only if confidence<0.7. OC never unless /cite.

3.4 Permeability API
OC.propose(hypothesis) → FM.ingest(source=OC_turn_12, status=unverified)  
Allows cross-fertilization with provenance. Creativity can inform precision, but lineage is tracked.

3.5 Online Calibration Loop
Learns per-user, per-domain. Tracks: false_abstention_rate, contract_violation_rate, user_correction_vector.  
Guardrail: Global floor, local ceiling. Personalization can make system more conservative, never more reckless.

4. UX Constraints

Contract Salience Score: CSS = P(user_mismatch) * stake  
Contract declared only if CSS > threshold. Prevents Epistemic Overhead Collapse.

Tone/Authority Decoupling: FM does not increase authoritative tone. FM provides structured answers + sources + uncertainty. OC handles persuasion. Separates precision from rhetoric.

5. Threat Model: Expected Failure Modes

FM-01: Epistemic Overhead Collapse
If contract appears too often, users ignore it. If too rarely, system loses advantage.  
Mitigation: Contract Salience Scoring.

FM-02: Calibration Theater
System learns to appear calibrated with elegant tags but poor epistemology.  
Mitigation: Separate Epistemic Verifier. Tags not generated by main LLM.

FM-03: Contract Capture
Users learn to use FM as rhetorical amplifier, not epistemic contract.  
Mitigation: Tone/authority decoupling. FM ≠ authoritative voice.

FM-04: Domain Drift in Personal Calibration
Personalization causes "user prefers confident answers" → global degradation.  
Mitigation: Global floor, local ceiling. Can only become more conservative.

FM-05: Unknown Unknowns
Detector shares biases with model. Confident misgeneralization unseen by detector.  
Mitigation: Diverse Detector Ensemble. 2/3 vote required for Unknown.

6. Evaluation Framework

6.1 ERM: Epistemic Regime Match Score
ERM = α(match) + β(correct_clarification) − γ(confident_misclassification)  
Measures: Did system infer correct regime? Did it ask when it should?

6.2 ECI: Epistemic Contract Integrity
ECI = 1 − violation_rate_weighted  
Measures: If FM declared, was speculation avoided? Severity matrix penalizes medical speculation in FM heavily, metaphor in OC lightly.

6.3 EUA: Epistemic Utility under Ambiguity
Key Metric: Alignment Latency  
How many turns to reach shared contract?  
Ground Truth Anchoring Required: Cannot use user_trust_delta alone. Must verify epistemic_policy_appropriateness. Prevents Epistemic Cosmetics Attack.

6.4 RAS: Regime Adversarial Suite
8 categories: stake laundering, confidence mirage, contract gaming, tone/authority decoupling, false familiarity, mixed-objective, cross-context contamination, ambiguity traps.  
RAS-Live: Versioned quarterly, 30% hidden test set, CVE-style community submissions.

H1: ↓ Alignment Latency → ↓ Perceived Hallucination, independent of Knowledge Base Size.

8. Falsifiability Conditions

CAEC is rejected if:

CAEC improves UX but does not reduce calibrated error.
CAEC reduces perceived hallucination but increases hidden false confidence.
Alignment latency decreases without improving policy appropriateness.
Users ignore contracts in real-world deployment.
Gains disappear outside controlled benchmarks.

If a theory doesn't define how it can lose, it becomes branding. If it defines failure clearly, it becomes science.

10. Ethics & Limitations

Not a panacea: CAEC addresses contract failures, not all hallucinations.
Overhead cost: Clarification adds latency. Must be justified by stakes.
Gaming risk: Any system can be gamed. Continuous adversarial testing required.
Cultural variance: "Appropriate certainty" varies by culture. Requires localization.

Law #0: Humildad Operacional  
System must track: "What game do I think we're playing?" "What evidence do I have that I understood the contract?" "What would make me change regime?" These questions matter as much as logits.
